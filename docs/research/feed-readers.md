# ほかのフィードリーダーの機能と、Feedability に足りないもの（調べたもの）

Feedability の機能を決めるときの参考。決定ではない。Reeder 5 は [reeder.md](reeder.md) に詳しく書いたので、ここでは差分だけを見る。

## 調べ方

- 調べた日：2026-10-19
- 対象：Inoreader、Feedly、Reeder（2024 年からの新しい版。旧版は Reeder Classic）、NetNewsWire
- 読んだもの：Web 検索の結果の抜粋（各社のブログ・ヘルプ・App Store の説明・MacStories や TechCrunch の記事）。この環境からはページを直接開けなかったので、抜粋の範囲でしか確かめていない。料金やプランの上限は古いページのものが混ざる
- 比べる相手の Feedability は 2026-10-18 時点（README の「機能」と ROADMAP の対応済み）

## 各リーダーの特徴

### Inoreader（Web サービス）

- **ルール**：新しい記事（アカウント全体・フィード・フォルダ）、タグ付け、あとで読むへの保存などをきっかけに動く。条件はタイトル・本文・著者・URL・添付・言語・RSS のカテゴリ。AND / OR で組み合わせ、正規表現も使える。動作はタグ付け・あとで読む・既読にする・通知（デスクトップ / プッシュ）・メール・メモ・要約・翻訳・Webhook・外部サービスへの書き出し
- **フィルタ**：条件に合わない記事を、届いた時点で隠す
- **重複の除去**：フィード・フォルダ・アカウント全体で、同じ記事やほぼ同じ記事をまとめる。ルールが重複のたびに動かないようにもなる
- **Spotlight**（旧 highlighters）：選んだ語句を本文で自動的に色付けする
- **ハイライトとメモ**：本文の一部を手でハイライトし、記事やハイライトにメモを付ける。あとでまとめて見返せる
- **検索**：全文検索。AND / OR・括弧・ワイルドカード。キーワードごとの「監視フィード」（Monitoring feeds）。購読の外の公開記事も探せる
- **取り込み元**：ニュースレター（専用のメールアドレス）、RSS の無いページ（Web feeds、ページの変化の追跡、要素を選んで監視）、YouTube（チャンネル・再生リスト）、SNS
- **あとで読む**：読む時間の目安、どこまで読んだか、メタデータの編集
- **そのほか**：読み上げ（TTS）、オフライン、翻訳、PDF に書き出し、ダッシュボード（第三者の記事のみ。未確認）

### Feedly（Web サービス）

- **Leo（AI）**：Priority（キーワード・トピック・出来事で大事な記事に印を付け、別のタブにまとめる）、Mute filters（トピックや語句を含む記事を全フィードで隠す。期間を決められる）
- **要約**：要点の文をハイライトする（上位プラン）
- **Boards**：記事を名前付きのボードに保存する（あとで読む・資料・共有）。チームで共有できる
- **メモとハイライト**、ニュースレター、重複の除去
- 新着の通知はアプリには無いという情報と、プッシュ通知があるという情報がぶつかる（未確認）

### Reeder（新しい版）

- **タイムライン**：RSS・YouTube・Reddit・Mastodon・Bluesky・ポッドキャストを 1 本のタイムラインに並べる。未読数を持たず、どこまで読んだか（タイムラインの位置）を端末間でそろえる
- **組み込みのタイムライン**：Home / Video / Audio（動画・音声を含む記事だけ）
- **フィルタで作るタイムライン**：キーワード（含む / 除く、複数。既定は単語の一致でワイルドカードも可）、メディアの種類、フィードの種類
- **Saved**：Links（共有メニューから入れたもの）/ Later / Bookmarks / Favorites と、自分で作るタグ（アイコン付き）。スワイプでタグを付ける
- 古い項目を消すタイムラインの設定、本文の幅、返信の字下げ（Mastodon / Bluesky）

### NetNewsWire（Mac / iOS、オープンソース）

- スマートフィード：**Today**（だいたい 24 時間以内）/ All Unread / Starred
- リーダー表示、共有、キーボードショートカット、OPML、フォルダ、ウィジェット、iCloud や各サービスとの同期
- 機能は Feedability と近い。足りないものの比較では **Today** くらい

## 足りないものの一覧

Feedability の方針（データはこの PC だけ・外への通信は `fetch.rs` だけ・WebView から外へ出さない）に照らして 3 つに分けた。規模は ROADMAP と同じ目安（S = 1〜2 日、M = 3〜5 日、L = 1〜2 週間以上）。

### A. 方針の中で足せるもの

| 機能 | どこにあるか | 規模 | メモ |
|---|---|---|---|
| **ミュート（除外）フィルタ**（対応済み、[MUTE.md](../MUTE.md)） | Feedly、Inoreader、Reeder | S〜M | 語句を含む記事を、保存するときに既読にする（または隠す）。フィードごと / 全体。まずはタイトルと要約に対して。ルールの最初の一歩にできる |
| **ルール**（形だけ対応済み。動作は既読にするだけ） | Inoreader、Feedly（Priority） | M | 条件（タイトル・本文・著者・URL・フィード）→ 動作（既読・スター・あとで読む・通知）。Rust の保存の処理で動かす。動作は元に戻せるものだけにする（Architecture §7） |
| **全文検索と検索の書き方**（対応済み、[SEARCH.md](../SEARCH.md)） | Inoreader | M | 今はタイトル・要約・フィード名の LIKE。本文（全文取得の本文を含む）を SQLite FTS5 で。`"語句"`・除外（`-語`）・OR。ROADMAP の後回しの「全文検索」と同じ |
| **保存した検索 / スマートフィード** | Reeder（フィルタのタイムライン）、Reeder 5、Inoreader（監視フィード） | M | 検索の条件をサイドバーの行として残す。ROADMAP の後回しの「保存した検索」と同じ。全文検索のあとがよい |
| **Today** | NetNewsWire | S | 24 時間以内の記事。サイドバーの「すべての記事」の下に 1 行。⌘1〜3 の並びに足すならキーも決める |
| **重複の検出** | Inoreader、Feedly | M | 同じ URL（クエリの追跡用パラメータを除いたもの）やほぼ同じタイトルの記事を、あとから来た方を既読にする。複数のニュースサイトや集約フィードを読む人に効く |
| **キーワードの強調**（Spotlight） | Inoreader | S | 登録した語句を本文と一覧で色付けする。ammonia で安全化したあとに、文字の部分だけに印を入れる |
| **読む時間の目安** | Inoreader | S | 一覧の行かあとで読むに「約 n 分」。日本語は文字数、英語は語数で数える |
| **記事ごとの全文取得** | Reeder 5、Reeder | S | 今はフィードごとのオン / オフ。オフのフィードでも、この記事だけページから取る操作（コマンド表に 1 つ）。ADR-0001 の範囲の確認が要る |
| **読み上げ** | Inoreader | S〜M | OS の音声（Web Speech API の `speechSynthesis`。macOS・Windows の音声で、外へは出ない）。WebView2 / WKWebView で使える声を先に確かめる |
| **新着の通知** | Inoreader（ルールの動作） | S〜M | ROADMAP の後回しにある。全部の新着だと多すぎるので、ルールの動作として「通知する」を選べる形がよい |
| **タグ** | Inoreader、Reeder、Reeder 5 | M | ROADMAP の後回しにある。あとで読む・スターと役割がぶつからないよう、先に分け方を決める |
| **ページの変化の追跡**（RSS の無いページ） | Inoreader | L | `fetch.rs` でページを定期的に取り、選んだ要素の変化を記事にする。取りに行く範囲が広がるので ADR-0001 の見直しが要る |
| **YouTube チャンネルの購読**（Y1・Y2 は対応済み、[YOUTUBE.md](../YOUTUBE.md)） | Reeder、Inoreader、Reeder 5 | S〜M | 購読はできるが、本文が空になっていた。下の「YouTube のチャンネル」 |

### B. 方針とぶつかるので、決めてから

| 機能 | どこにあるか | ぶつかるもの |
|---|---|---|
| 動画・音声の再生（YouTube の埋め込み、ポッドキャスト） | Reeder、Inoreader | WebView から外へ出る（CSP に外の出どころを足す）。ポッドキャストを Rust で落としてから再生するなら CSP は触らずに済むが、L |
| Mastodon / Bluesky / Reddit のタイムライン | Reeder | アカウントへのログインと API への通信。公開の RSS（Mastodon のユーザー、Bluesky のプロフィール、Reddit のサブレディット）を読むだけなら A に入る |
| 要約・翻訳 | Feedly、Inoreader | 外部の AI や翻訳サービスへの通信。フェーズ 8（MCP）で Claude 側にやらせる形なら Feedability から外へは出ない |
| ハイライトとメモ | Inoreader、Feedly | 方針とはぶつからないが、取っておく情報は stockroom の役割。Feedability ではしない方がよさそう |

### C. 対象外

| 機能 | どこにあるか | 理由 |
|---|---|---|
| 端末間の同期 | すべて | ADR-0002（データはこの PC だけ、アカウントもサーバーも持たない） |
| ニュースレターをメールで受け取る | Inoreader、Feedly | 受け取るメールアドレス（サーバー）が要る |
| チームでの共有、ボードの共有 | Feedly、Inoreader | サーバーが要る |
| 購読の外の記事を探す検索 | Inoreader | サーバー側の索引が要る |

## YouTube のチャンネル

### YouTube のフィード

- URL：`https://www.youtube.com/feeds/videos.xml?channel_id=UC…`（チャンネル）、`?playlist_id=…`（再生リスト）。Atom
- 中身は新しい動画のおよそ 15 本だけ。ショート動画もふつうの動画と一緒に入る。ショートだけのフィードは無い
- 再生リストのフィードで、チャンネル ID の先頭 `UC` を `UULF` に替えるとショートを除いた動画、`UUSH` にするとショートだけになる、という方法がコミュニティでは知られている（公式ではない。確かめていない）
- 2025 年 12 月ごろから、`videos.xml` がときどき 404 や 500 を返すという報告が続いている（Invidious、FreeTube、newsboat などの issue）。データセンターの IP からが多いとされるが、家庭の IP でも出るという報告もある。YouTube からの公式の説明は見つからなかった

### Feedability で今どうなるか

コードを読み、`feed-rs` 3.0.0（Feedability と同じ版）で YouTube と同じ形のフィードを読む小さな試験をした（scratchpad。リポジトリには入れていない）。実物の YouTube にはこの環境から繋がらず、試していない。

| 項目 | 結果 |
|---|---|
| 購読（チャンネルのページの URL を入れる） | チャンネルのページには `<link rel="alternate" type="application/rss+xml">` があるので、`feed::discover` で見つかるはず。EU などで同意のページ（`consent.youtube.com`）へ飛ばされると見つからない |
| タイトル・リンク・日付・投稿者 | 取れる |
| 縮小画像 | `media:thumbnail`（`i.ytimg.com` の画像）が `thumb_url` に入る。「画像付き」の一覧に出る |
| **本文と一覧の冒頭** | **空になる**。YouTube は説明文を `<media:group>` の `<media:description>` に入れていて、`feed-rs` ではこれが `summary` / `content` でなく `media[].description` に入る。`feed.rs` の `article()` は `content` か `summary` からしか本文を作らない |
| 全文取得 | 動画のページから本文は抜き出せないので、使えない |
| アイコン | チャンネルのページの `<link rel="icon">` を取る（YouTube のアイコンになる。チャンネルの顔写真ではない） |
| 更新できないとき | 404 / 500 が出ると、ほかのフィードと同じくサイドバーに赤い印が付く。上の不安定さがそのまま見える |

### 足すとしたら

| # | 中身 | 規模 | 方針との関係 |
|---|---|---|---|
| Y1 | 本文が空で `media:description` があれば、それを本文にする（改行を `<br>` に、URL をリンクに）。先頭に縮小画像を置き、押すとブラウザで動画を開く。YouTube に限らず、`media:group` だけのフィード（ポッドキャストや画像のフィードの一部）にも効く | S | 変わらない（画像は今と同じく Rust が取る） |
| Y2 | `/@名前`・`/channel/UC…`・`/c/…`・`/user/…`・`watch?v=` の URL を入れたら、ページからフィードの URL を見つける。見つからないとき（同意のページなど）は `channel_id` を探して組み立てる | S | 変わらない |
| Y3 | ショートを含めるかを購読のときに選ぶ（上の `UULF` の再生リストにする） | S | 変わらない。公式でない方法なので、使えなくなったら元のフィードに戻せるようにしておく |
| Y4 | 404 / 500 のときに間隔を空けて取り直す | S〜M | 変わらない。ROADMAP の後回しの「失敗したフィードの間隔を空けた再試行」と同じ |
| Y5 | アプリの中で動画を再生する | M | **ぶつかる**。YouTube の埋め込み（`youtube-nocookie.com` の iframe）は WebView から外へ出るので、CSP の緩和が要る（CLAUDE.md の「変えないもの」）。ブラウザで開く今の形のままがよい |

Y1 と Y2 を入れれば、YouTube のチャンネルを「新しい動画の知らせ」として読める。再生はブラウザに任せる。

**その後**：Y1 と Y2 は対応済み（[YOUTUBE.md](../YOUTUBE.md)、#22）。Y3〜Y5 は決めていない。

## 優先の案

読む量を減らす機能（A の上の方）が、どのリーダーにもあって Feedability に無い一番大きなところ。方針ともぶつからない。

1. **ミュートフィルタ**（S〜M）→ そのまま **ルール**（M）へ広げる。条件と動作の形を最初にルールとして決めておき、ミュートは「既読にする」動作のルールとして入れる
2. **全文検索（FTS5）**（M）→ **保存した検索 / スマートフィード**（M）と **Today**（S）
3. **重複の検出**（M）
4. 小さいもの：キーワードの強調、読む時間の目安、記事ごとの全文取得、YouTube チャンネルの購読（どれも S）

ROADMAP のフェーズ 8（MCP）より前に 1 と 2 を入れると、MCP で公開する「検索」と「既読にする」の土台にもなる。

**その後**（2026-10-19）：1 のミュート（ルールの形で、動作は既読にするだけ。#23）、2 の全文検索（#24）、4 の YouTube チャンネルの購読（#22）は対応済み。残りは、ルールの動作を増やす、保存した検索 / スマートフィード、Today、重複の検出、4 の小さいもの。
