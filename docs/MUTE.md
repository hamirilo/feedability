# ミュート

困っていること：興味のない話題（広告の記事、セール、特定の製品）が毎日いくつも届き、1 件ずつ既読にしている。

ほかのリーダーでは Feedly の Mute filters、Inoreader の Filters / Rules、Reeder のフィルタにあたる（[research/feed-readers.md](research/feed-readers.md)）。

## 決定

- **ミュートの語句**：タイトルか要約に語句を含む **新しい記事を、保存するときに既読にする**。記事は消さない（「未読のみ」を外せば見える）
  - 合わせ方は検索と同じ：空白で区切ると、すべてを含むもの。大文字と小文字は区別しない
  - 場所：すべてのフィード / 1 つのフォルダ / 1 つのフィード
  - 既読にした記事は全文取得の対象にしない（読まない記事のページを取りに行かない）
  - 「保存したページ」（ブラウザ拡張から入れたもの）には効かない。自分で選んだ記事なので
- **追加したとき**：今ある未読の記事にもすぐ当てはめる。既読にした件数をトーストで知らせ、「元に戻す」で戻せる（「すべて既読」と同じ）
- **オン / オフと削除**：新しい記事に効かなくなるだけ。すでに既読にした記事は既読のまま。語句の変更は、削除して追加し直す
- フィードを購読をやめる・フォルダを削除すると、そこのミュートも消える
- **ルールの形**：中身は「条件（語句と場所）→ 動作（既読にする）」のルールとして持つ。動作を足せば（スター・あとで読む・通知）、ROADMAP の「ルール」に広げられる。今の動作は既読にするだけ
- **置き場所**：設定（⌘,）›「ミュート」のページ。フィード / フォルダの右クリックとメニューの「フィード」に「ミュートする語句を追加…」。開いているフィードかフォルダが場所として選ばれた状態で開く
- キーは割り当てない

## 実装

- DB（スキーマ v7）：`rules`（`words`・`feed_id`・`folder_id`・`action`（今は `'read'` だけ）・`enabled`・`created_at`）。`feed_id` と `folder_id` は `ON DELETE CASCADE`。古いアプリはこの表を見ないので、v7 のファイルを開いてもミュートが効かないだけ
- Rust：`db.rs` の `Rule::matches`・`rules`・`add_rule`・`set_rule_enabled`・`delete_rule`・`apply_rule`。`store_articles` が新しい記事を入れるときに、そのフィードに効くルールで `read` を決める（更新で既にある記事は触らない）。コマンド `list_rules`・`add_rule`（追加して今ある未読に当てはめ、既読にした id を返す）・`set_rule_enabled`・`delete_rule`
- 画面：`src/components/MuteSettings.tsx`。ストアの `addRule`（元に戻すのトースト）、コマンド `feed.mute`。モック（`src/dev/mockBackend.ts`）も同じ動き
- 合わせるのは要約（`summary`、本文の先頭 400 文字の文字）まで。本文の全体は見ない
